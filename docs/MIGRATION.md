# Переезд на новый сервер — порядок и чеклист

Роли: **ИТ** — новый сервер, сеть, запуск скриптов; **владелец сервисов** — проверка
работы, пользователи, MSSQL-привязки.

## До дня переезда

- [ ] Новый сервер: Ubuntu 24.04, ≥4 ГБ RAM, ≥40 ГБ диск, статический IP в офисной сети
- [ ] С нового сервера доступны: `10.100.1.110:1433` (MSSQL), `botapi.max.ru`, `api.perplexity.ai`, `cbr.ru`, Битрикс
      (`nc -zv 10.100.1.110 1433`, `curl -I https://botapi.max.ru`)
- [ ] `git clone https://github.com/Trest-SZMA/AI_MOT.git /opt/AI_MOT` и `sudo deploy/install.sh` — прошёл без ошибок
      (сервисы поднимутся с пустыми env-файлами и будут ругаться — это ожидаемо до импорта данных)
- [ ] Пробный прогон импорта: на старом сервере `export-data.sh`, перенести архив,
      на новом `import-data.sh` (бота **не** запускать — ответить N). Открыть портал, каждый сервис.
      Реализация и Остатки → «Обновление данных» → «проверить» MSSQL.
- [ ] Согласовать окно переключения: **после 05:00 и до 01:00**, чтобы не попасть в ночную
      выгрузку 1С (01:00), бэкапы (02:30, 03:30) и пересборку (04:00). Лучше утро рабочего дня.

## День переезда

1. Предупредить пользователей: сервисы недоступны ~30 минут.
2. **Старый сервер**: остановить бота — `systemctl stop logistmot-bot` (иначе два бота будут отвечать вразнобой).
3. **Старый сервер**: `sudo bash /opt/AI_MOT/deploy/export-data.sh` → архив; `scp` на новый.
4. **Старый сервер**: остановить остальные службы, чтобы никто не писал в старые данные:
   ```bash
   systemctl stop bp-service fines-service logistmot-panel metallompro metoptorg-kp metoptorg-ostatki metoptorg-portal metoptorg-realizaciya parser-bp
   systemctl disable metoptorg-realizaciya-nightly.timer metoptorg-kp-backup.timer metoptorg-bp-weekly.timer metoptorg-healthcheck.timer metoptorg-healthcheck-summary.timer
   ```
5. **Новый сервер**: `sudo deploy/import-data.sh /root/ai_mot_data_*.tar.gz` — на вопрос про бота ответить `y`.
6. **Новый сервер**: `sudo deploy/check.sh` — всё `active`, все порты отвечают.
7. Проверка руками (владелец сервисов):
   - [ ] портал `http://НОВЫЙ_IP:8079` — вход, все плитки ведут на новый IP
   - [ ] Реализация — «Обновление данных» → проверить MSSQL → нажать «Пересобрать», дождаться, сверить итоги с последней сборкой на старом сервере
   - [ ] Остатки — то же
   - [ ] Оценка КП — вход под своей учёткой, открыть любой сохранённый КП, **загрузить** тестовый файл (проверка записи в базу)
   - [ ] Бизнес-планы — `https://НОВЫЙ_IP:8443`, открыть БП с вложением
   - [ ] ЛогистМОТ — написать боту в MAX, увидеть ответ; панель 8080
   - [ ] Штрафы, Парсер БП, MetalLomPro — открываются, данные на месте
8. Сообщить пользователям новый адрес (или перенести старый IP на новый сервер — тогда шаг не нужен).
9. Healthcheck: убедиться, что `/etc/metoptorg-healthcheck.env` заполнен, `metoptorg-healthcheck --test` доставляет сообщение в MAX.

## После переезда

- [ ] Старый сервер выключить (не удалять) и держать 2 недели на случай отката
- [ ] На следующее утро проверить, что ночная пересборка прошла: `systemctl status metoptorg-realizaciya-nightly`, сводка healthcheck в 08:00
- [ ] Файрвол на новом сервере: порты 8077–8095, 8443 — только из офисной подсети; 22 — только для ИТ
- [ ] Заменить самоподписанный сертификат bp-service (`deploy/make-cert.sh`) на корпоративный, если есть

## Откат

Старый сервер не менялся: `systemctl start` всех служб и таймеров на нём, выключить новый.
Данные, введённые пользователями на новом сервере после переключения, при этом теряются —
поэтому окно проверки (шаг 7) должно быть коротким и до объявления адреса.
