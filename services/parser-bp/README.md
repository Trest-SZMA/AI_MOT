# Парсер БП — проверка количества месяцев вывоза

Программа обходит папку с бизнес-планами (Excel), находит на листах блок
**«Расчет процентов»** и проверяет два способа определения количества месяцев вывоза:

| Способ | Что берётся |
|---|---|
| **По строкам** | сколько строк «Привлеченный капитал за N месяц» имеют проставленный порядковый номер месяца (столбец «Порядковый номер месяца по убыванию») |
| **По ячейке** | значение строки «Кол-во месяцев вывоза» |

Статусы строк отчёта:

| Статус | Цвет | Что означает |
|---|---|---|
| ОК | зелёный | оба способа дали одно число |
| Расхождение | красный | числа разошлись; в столбце «Расхождение» написано, где и на сколько |
| Не заполнен | серый | блок скопирован из шаблона, но расчёт не вёлся: ни порядковых номеров, ни сумм капитала. Отделён от расхождений, иначе пустые заготовки топят реальные ошибки — на боевой папке их 456 против 164 настоящих расхождений |
| Не определено | жёлтый | блок найден, но одно из значений прочитать не удалось |

---

## Запуск

### Windows (у экономиста)

1. Скопировать всю папку с программой **на локальный диск** (например, `C:\ПарсерБП`).
   Из сетевой папки запускать не нужно — программе требуется право записи в свою папку.
2. Один раз установить **Python 3.11 – 3.14** с https://www.python.org/downloads/
   — при установке **обязательно** поставить галочку **«Add Python to PATH»**.
3. Двойной щелчок по **`ЗАПУСТИТЬ.bat`**.
   При первом запуске 1–3 минуты ставятся библиотеки **из локальной папки `packages`
   — интернет не нужен**, затем открывается вкладка в браузере.
4. Выбрать папку с БП: кнопка **«📂 Выбрать папку…»** (обычное окно Windows),
   либо **«🗂 Навигатор по папкам»**, либо просто вставить путь в поле.
   Выбранный путь запоминается до следующего запуска.
5. Нажать **«▶️ Запустить проверку»**.
6. Кнопка **«⬇️ Скачать отчёт в Excel»** сохраняет файл `Проверка_БП_ГГГГ-ММ-ДД_ЧЧ-ММ.xlsx`
   с той же зелёной/красной заливкой + листами «Сводка» и «Пропущенные файлы».

Закрыть программу — просто закрыть чёрное окно консоли.

### macOS (для разработки/проверки)

```bash
./run.command
```

## Офлайн-установка (папка `packages`)

В комплекте лежит папка **`packages`** — все библиотеки заранее скачаны туда
(69 файлов, ~245 МБ). `ЗАПУСТИТЬ.bat` ставит их командой
`pip install --no-index --find-links packages`, то есть **доступ в интернет не нужен**.

Что важно знать:

* Пакеты собраны под **Windows 64-бит** и **Python 3.11 / 3.12 / 3.13 / 3.14**.
  Часть библиотек (numpy, pandas, pyarrow) — бинарные и жёстко привязаны к версии
  Python, поэтому на 3.10 и более старых они не встанут.
* Если версия не совпала, `.bat` не молчит, а печатает версию Python
  и что делать дальше.
* Если папку `packages` удалить, `.bat` попробует поставить библиотеки из интернета.

### Пересборка папки `packages`

На машине **с интернетом** (можно с macOS — колёса скачиваются под Windows):

```bash
./собрать_пакеты.sh 3.15
```

Без аргументов собираются версии 3.11–3.14. Одна версия Python ≈ 60–80 МБ,
общие пакеты между версиями не дублируются.

## Выбор папки

Три способа, все делают одно и то же:

| Способ | Когда удобен |
|---|---|
| **📂 Выбрать папку…** | обычное окно Windows; работает и на удалённом рабочем столе |
| **🗂 Навигатор по папкам** | если системное окно не открылось (урезанная сборка Python без tkinter) — переход по папкам кнопками, в Windows сверху список дисков |
| Поле «Путь к папке с БП» | быстрее всего вставить готовый сетевой путь `\\сервер\папка` |

Системный диалог запускается **отдельным процессом** — так он не подвешивает
приложение и не конфликтует с потоками Streamlit. Если tkinter в системе нет,
появится предупреждение с предложением воспользоваться навигатором.

## Работа с сетевыми и удалёнными папками

* В поле пути можно вводить как локальный путь (`D:\БП`), так и сетевой (`\\server\share\БП`).
* Программа **никогда не пишет** в исходные файлы: каждый файл копируется во временный
  каталог, читается оттуда и временная копия удаляется. Поэтому файл не блокируется
  у коллег и обрыв сетевого соединения не портит оригинал.
* Файл, открытый кем-то в Excel, всё равно прочитается (временные файлы `~$...` пропускаются).
* Если файл недоступен или повреждён — он попадёт в список «Пропущенные файлы»
  с причиной, а обработка остальных продолжится.
* На сетевой папке скорость упирается в сеть: локальная папка из 7 книг (90 листов)
  обрабатывается примерно за 1,5 секунды.

## Что программа читает

* Форматы: `.xlsx`, `.xlsm`. Старый `.xls` не читается — такие файлы попадают
  в «Пропущенные» с просьбой пересохранить как `.xlsx`.
* Просматриваются **все листы** каждой книги (галочку «Только листы, содержащие v0»
  можно включить для ускорения, если блок всегда на v0-листах).
* Положение блока на листе не фиксировано — он ищется по тексту «Расчет процентов»
  (а если заголовка нет — по строке «Кол-во месяцев вывоза»). Регистр, `ё/е`
  и лишние пробелы значения не имеют.
* Если на одном листе несколько блоков — в отчёт попадут все.

## Столбцы отчёта

| Столбец | Описание |
|---|---|
| Название БП и версия | `БП 1545_23.05.2025 \| v0 21.05.2025_лук` — номер и дата из имени файла + имя листа |

## Деплой на сервер 192.168.6.157

Сервис развёрнут в `/opt/parser-bp`, слушает порт **8093**, плитка на портале
http://192.168.6.157:8079 (раздел «МетОптТорг»).

| Что | Где |
|---|---|
| Код | `/opt/parser-bp` (venv в `.venv`) |
| Служба | `parser-bp.service`, юнит — `deploy/parser-bp.service` |
| Пароль и режим | `/etc/parser-bp.env` (права 600) |
| Плитка портала | запись `parserbp` в `/opt/metoptorg-portal/web/services.json` |

Переменные в `/etc/parser-bp.env`:

* `PARSER_BP_SERVER=1` — прячет системный диалог выбора папки (на сервере он
  открылся бы на самом сервере) и делает режим загрузки файлов основным;
* `PARSER_BP_PASSWORD=…` — пароль входа. Пустое значение = вход без пароля,
  поэтому локально в Windows экран входа не появляется.

Обновление кода:

```bash
rsync -az --delete --exclude '.venv' --exclude '__pycache__' --exclude 'packages' --exclude 'bat_src' --exclude '*.bat' -e "ssh -i ~/.ssh/fines_deploy" ./ root@192.168.6.157:/opt/parser-bp/ && ssh -i ~/.ssh/fines_deploy root@192.168.6.157 'systemctl restart parser-bp'
```

### Три режима работы с файлами

На сервере приложение видит **только свою файловую систему**, поэтому папка с БП
с компьютера экономиста ему недоступна. Отсюда два режима:

* **Ссылка Битрикс24** — вставляется публичная ссылка «Поделиться» на папку Диска
  (`https://team.rosmetrade.ru/~XXXXX`). Программа обходит папку и подпапки, качает
  книги во временный каталог, разбирает и удаляет. Учётные данные не нужны.
* **Загрузить файлы** — книги отправляются через браузер, разбираются во временном
  каталоге и сразу удаляются; на сервере ничего не остаётся. Работает всегда.
* **Папка** — обход каталога, доступного серверу. Чтобы работал с сетевой шарой,
  её нужно примонтировать на сервере (`/etc/fstab`, cifs) — тогда экономисту
  не придётся ничего загружать вручную.

## Правка .bat-файлов — важно

`.bat` в корне **нельзя редактировать напрямую в macOS-редакторе**: он сохранит
файл с переводами строк LF и в UTF-8, а cmd.exe требует **CRLF и cp866**.
При LF Windows не находит метки `goto` и окно закрывается сразу после запуска,
не показав ни одной ошибки — именно на это легко потратить час.

Правильный путь: править исходники в `bat_src/` (обычный UTF-8), затем

```bash
python3 пересобрать_bat.py
```

Скрипт проверяет, что у каждого `goto` есть метка и что весь текст кодируется
в cp866, и только потом перезаписывает файлы в корне.

## Если понадобится .exe без установки Python

На **Windows**-машине с установленным Python выполнить в папке программы:

```bash
pip install pyinstaller && pyinstaller --onefile --name ПарсерБП app.py
```

Streamlit-приложения в один exe упаковываются с оговорками; проще и надёжнее
раздать папку с `ЗАПУСТИТЬ.bat`.
