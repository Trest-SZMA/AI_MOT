# Сервис подготовки бизнес-планов МетОптТорг (v2)

Модель данных и расчёты построены по реальному БП (лот №1759 Лукойл-Пермь/Коми)
и отчёту о прибылях и убытках. Менеджер, логист и экономист заполняют каждый
свой раздел одной карточки, P&L считается по утверждённой методике, маршрут
сделки рисуется графом, на выходе — 6 файлов (БП xlsx с формулами + Word +
4 таблицы для 1С/Битрикс24).

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python pull_1c.py                              # ночная выгрузка из MSSQL Extractor (справочники,
                                                # склады, подразделения, группы)
python import_1c_csv.py /путь/к/csv-выгрузкам   # CSV 1С: серии, статьи расходов,
                                                # статистика цен/засора/тарифов
python seed.py                                  # настройки + номенклатура (синергия с 1С)
uvicorn app.main:app --reload                   # http://localhost:8000
```

Деплой на сервер (systemd + nginx + бэкапы): `deploy/README.md`.

## Варианты расчёта «ДСП» и «Лукойл»

Экономисты считают каждый БП в двух вариантах — пары листов книги
«БП/v0 ..._дсп» (внутренний расчёт, вариант **ДСП**) и «БП/v0 ..._лук»
(вариант **Лукойл**). В карточке БП — переключатель вариантов (вверху):

- у варианта «Лукойл» свои цены реализации позиций (`bp_items.sale_price_luk`),
  свои суммы статей затрат (`bp_costs.amount_luk`; NULL = как в ДСП) и
  переопределения параметров сделки (`business_plans.luk_overrides`, JSON —
  например срок вывоза: в БП 1929 дсп = 4 мес, лук = 5 мес);
- при импорте книги базовым становится актуальное семейство листов
  (первое по порядку книги; при паре одной даты базовый — «дсп», «лук» —
  второй вариант); контрольные суммы обоих вариантов сохраняются и
  сверяются — плашка «сходится с файлом» у переключателя;
- P&L, аукционная лестница, сценарии, график, план-факт и экспорт считаются
  по активному варианту; в экспорт дополнительно кладётся xlsx второго
  варианта; при has_luk в таблицах появляются парные колонки «ДСП»/«Лукойл»;
- срок вывоза для капитала выводится и из строки «Стоимость привлечённого
  капитала» (обратный расчёт), когда метки «кол-во месяцев вывоза» в книге
  нет (книги РИТЭК/Печорская 2026);
- нестандартные статьи файла («Страхование груза» БП 1928) переносятся
  новыми строками затрат с секцией по положению в блоках P&L;
- сложные книги (БП 1785, лом ЧМ + ЦМ): цветной лом, записанный экономистом
  с типом «лом» (латунь/медь/нержавейка), переклассифицируется в «цветмет»
  с построчным засором (ЦМ 5% при ЧМ 6%); база капитала может отличаться от
  закупки (business_plans.capital_base — в 1785 закуп без меди), срок
  капитала может быть дробным (0,25 = неделя) и выводится обратным расчётом
  из строки «Стоимость привлечённого капитала» (точнее меток шапки);
  подчёркивания и пробелы в именах листов взаимозаменяемы
  («БП_24.12.2025 лук+дсп» + «v0 24.12.2025_лук+дсп» — одна пара).

Проверка на реальных книгах: 1865, 1674 (+сценарий «минус 1000»), 1738,
1692, 1785 (ЧМ+ЦМ, база/срок капитала), 1855, 1923, 1926, 1928,
1929 (оба варианта), 1931, 1933, 1935 —
операционная и чистая прибыль воспроизводятся до копейки по каждому
распознанному варианту. Известные ограничения: кабельные книги с разборкой
и повторными блоками (1927) — импорт покажет расхождение с контролем.

## Данные 1С (CSV) и автоподсказки

`import_1c_csv.py` загружает CSV-выгрузки 1С (серии/лоты, номенклатуру,
склады, статьи расходов с правилами распределения, производственные
подразделения) и строит компактную статистику для подсказок:
фактические цены закупки по контрагентам и группам (`stat_purchase_price`),
цены реализации по группам и дивизионам (`stat_sale_price`), засор по
местам погрузки (`stat_contamination`), тарифы перевозки (`stat_transport`),
ставки переработки по видам работ (`stat_processing`). Подробности —
`docs/import_1c_csv.md`. В карточке БП блок «Лот» показывает ориентиры
из этих данных (панель «Ориентиры из фактических данных 1С»).

## Доработки по встрече с экономистом (10.08.2026)

Разбор записи — `docs/Требования_экономиста_2026-08-10.md` (там же статусы
всех пунктов), расшифровка — `docs/Запись_экономиста_2026-08-10_транскрипт.txt`.
Реализовано:

- **Отсрочка оплаты покупателем** (`payment_delay_months`): «месяц на вывоз,
  месяц на дебиторку». Остаток капитала гасится не по отгрузке, а по ОПЛАТЕ —
  на N месяцев позже; срок может быть дробным (0,25 = неделя). Без отсрочки
  методика прежняя (Σ = база × ставка/12 × (мес+1)/2, сверено с БП 1865).
- **Фотографии лота** (блок «7а» карточки): загрузка нескольких снимков,
  дата съёмки из EXIF (или вручную), миниатюры, просмотр оригинала. По
  спорным лотам (1785/1885) фото с датой — аргумент при согласовании засора.
- **Кратность партий покупателя** (`bp_items.batch_size_t`): машина берёт
  объём кратно 20 тн, остаток («хвост») показывается в составе лота и
  подставляется в поле разделения строки — его вывозят на переработку или
  отдают другому покупателю.
- **Коэффициенты нормативов по номенклатуре** (`norm_nomen_factors`):
  резка штанги/НКТ съедает газа в 1,5–2 раза больше нормы — коэффициент
  умножает расход кислорода, бензина и смены резчиков. Справочник
  редактируется в «Справочниках».
- **Тарифы погрузки по местам** (`loading_tariffs`): у части поставщиков
  (Советский, Когалым) грузят своим краном — затрат нет; в остальных местах
  кран нанимается по тарифу за машину (неполная — по доле тарифа).
  Отдельная статья модели «Наём крана на погрузку».
- **Сезонность зимников** (`seasonal_access`): месяцы, когда на место можно
  заехать. Кнопка «Распределить автоматически» на графике вывоза кладёт
  объём базы только в доступные месяцы (зимник — декабрь-апрель), недоступные
  подсвечиваются; календарные месяцы подписаны от «Месяца начала вывоза».
- **Доля невозмещённого НДС** — подсказка по правилу экономистов: доходный
  БП принимает 100%, убыточный — долю, выводящую ЧП в ноль (РИТЭК 1935: 30%).
- **Этапы затрат** (`norms.STAGES`): каждый компонент модели отнесён к этапу
  движения металла — «Вывоз с цеха на базу», «Переработка на базе»,
  «Отгрузка с базы». В блоке «Затраты» — сводка по этапам с суммой, руб/тн
  своего драйвера (вывезенного / переработанного / отгруженного объёма) и
  расшифровкой по базам, плюс консолидация «Итого цех + база». У цеха и базы
  разные штат, управление и нормативы — теперь видно, где именно затратная
  часть. В графике вывоза у каждой базы появился блок «Переработка на базе»:
  мощность по нормативам базы (ручная резка + пресс × смены), зеркальный
  приход на базу по месяцам и запас мощности — отрицательный подсвечивается
  (база не успевает переработать приходящий объём).

- **Линии графа маршрута = затраты**: сумма на стрелке больше не привязывается
  руками, а считается из таблиц БП — этап «Вывоз с цеха на базу» ложится на
  входящие стрелки узла базы, «Отгрузка с базы» — на исходящие (в первую
  очередь путь к покупателю), «Переработка на базе» — на сам узел; внутри
  этапа сумма делится между путями по тоннажу. На стрелке видно
  «тоннаж · руб · руб/тн», на узле базы — «переработка N руб · N руб/тн».
  Статьи вне модели (административные, прочие), привязанные вручную,
  добавляются сверху. Блок «Экономика маршрута» сверяет: на стрелках + на
  узлах = итог модели (на БП 1865: 25,7 млн + 65,9 млн = 91,6 млн, расхождение
  0). Меняется цена ГСМ, доля собственного транспорта или состав позиций —
  цифры на графе пересчитываются сами.

## Расчётные таблицы из книг экономистов (разбор БП 1785, Астрахань)

Книга содержит 5 скрытых листов с расчётами, которых не было в сервисе.
Перенесено:

- **Экономика по базам** (блок «10а» карточки; лист «ЗС НКТ+ЛОМ»): по каждой
  базе — объёмы закупки и продажи, цена, себестоимость закупки, валовый
  доход, логистика, переработка, капитал и прибыль, в руб/тн и рублях.
  Суммы фактические (статьи БП), разрез логистика/переработка — по
  нормативной модели; сумма прибыли баз равна прибыли до налогообложения.
- **Свод по типам металла** (лист «бизнес-план для МСК»): объём, цена,
  себестоимость, затраты и прибыль на тонну по каждому типу — так
  руководство сравнивает сделки. В лоте с цветметом видно, что чёрный лом
  «тянет» стоимость: по 1785 лом −123 236 руб/тн против цветмета +461 526.
- **Плановый P&L по месяцам** (страница план-факта; лист «анализ фин»):
  13 показателей от выручки до чистой прибыли, разложенных по месяцам
  пропорционально плановой реализации, в рублях и руб/тн, с колонкой ИТОГО.
- **Обоснование ставки распределяемых расходов** (справочники; лист
  «распределяемые»): фактические косвенные расходы из 1С
  (`stat_overheads`, выгрузка «_Распределение_прочих_расходов_») по
  подразделениям и статьям, делённые на объём продаж — 24 465 993 руб /
  405 269 тн = **60,37 руб/тн** вместо «магического» норматива.
- **Портфель лотов** (`/portfolio`; лист «анализ фин», реестр лотов года):
  все БП одной таблицей — тоннаж, стоимость лота, план вывоза и остаток без
  плана, выручка, чистая прибыль, ROS, оборачиваемость (12 / срок вывоза) и
  фактическая выручка из план-факта.
- **Реквизиты перечня продавца** (блок в составе лота; лист «база данных»):
  балансовая стоимость, условия хранения, состояние лома, наличие
  техдокументации, необходимость дополнительных работ — подтягиваются с
  листа-перечня и связываются с позициями по наименованию.
- **Аукцион в двух ценах** (лист «расчеты по лоту»): к лестнице добавлены
  колонки «Лот с НДС» и «руб/тн с НДС» — в этих ценах идут торги.

Не реализовано и вынесено на встречу: раздельные нормативы уровня «цех»
(сейчас переопределения только по базам), длительность рейса по расстоянию
для командировочных, структурированные поля комментариев менеджера.

## Интерфейс

- **Подсказки при наведении**: у расчётных значений (KPI, строки P&L,
  статьи модели затрат, колонки таблиц) поповер объясняет, как значение
  получено, по какой формуле и как его быстро рассчитать (единый компонент
  в `base.html`, атрибут `data-tip`; старые `title` подхватываются
  автоматически).
- **Правки таблиц**: при изменении любого поля появляется липкая панель
  «Есть несохранённые изменения — Сохранить», уход со страницы с правками
  подтверждается; изменённые поля подсвечиваются.
- Адаптивность: таблицы компактнее на экранах до 760px, переключатель
  вариантов и KPI перестраиваются, широкие таблицы — в горизонтальном
  скролле со липкой шапкой.

## Модель (базовый БП — 1865 Лукойл-Западная Сибирь, сверено с 1759)

- **Закупка лотом**: цена руб/тн = стоимость лота / суммарный тоннаж позиций.
- **Позиции** привязаны к поставщику / подразделению / месту хранения;
  база позиции = «Поставщик», а при его отсутствии — подразделение (в БП 1865
  базы Лукойла лежат в «Подразделении»).
- **Засор** снимает объём продажи у чёрного лома по типу ПРОДАЖИ: труба,
  проданная ломом, теряет объём так же, как купленный лом (в 1865 — 5%).
- **Тип покупки ≠ тип продажи** (труба → лом): невозмещённый НДС считается
  автоматически; на затраты относится доля `vat_unrecovered_pct` (по умолчанию
  50% — строка «НДС, не возмещенный 50%» БП 1865), при расчёте налога на
  прибыль эта сумма добавляется обратно к базе (формула C53 БП 1865).
- **Ставка НДС** — 22% с 2026 (настройка `vat_rate`); при импорте готового БП
  выводится из пары «Себестоимость без/с НДС».
- **Привлечённый капитал**: база = закупка с НДС по типам (лом без НДС),
  остаток убывает линейно за срок вывоза, проценты = остаток × ставка / 12
  (в 1865: Σ = база × 23%/12 × 3,5 при 6 мес — совпадает до копейки).
- **Налоги с ФОТ** — автоматически от статьи «Зарплата» (49,7%, настройка).
- **Затраты по позициям**: каждая статья распределяется на позиции своей базы
  (поле «база» статьи или стрелка графа, к которой она привязана), без
  привязки — на все позиции по тоннажу; итог P&L — сумма позиций,
  Σ прибыли позиций = прибыль до налогообложения.
- **P&L**: выручка по типам → себестоимость лота → валовый доход → переменные →
  постоянные → операционная прибыль → капитал → налог → чистая прибыль.
- **Сценарии-варианты** (`bp_scenarios`): каждый сценарий переопределяет
  параметры сделки (сдвиг цены, порог закупки, доля невозмещённого НДС,
  ставки) и пересчитывается полным P&L; при импорте книги со сценарными
  листами («БП ..._лук (-1000)») сценарии создаются автоматически, с
  контрольной ЧП из файла для сверки. Черновые листы без цен (дсп)
  сценариями не становятся.
- **Проверка**: импорт файла 1865 воспроизводит все строки P&L до копейки
  (выручка 555 724 707,20; опер. прибыль 49 475 602,43; ЧП 14 132 977,81),
  включая построчную экономику (Q/R позиций). Файл 1674 (два сценария):
  базовый ЧП 19 205 087,45 и сценарий «минус 1000» (цена −1000, НДС 30%,
  порог 67,8 млн) ЧП 17 018 954,35 — оба до копейки.

## Расчётные блоки (из файла экономистов, лот 1759)

- **Построчная экономика**: прибыль каждой позиции (затраты и капитал
  распределяются на 1 тн), покупатель/вид отгрузки/ответственный на позицию.
- **Нормативный калькулятор затрат** (`app/norms.py`): статьи считаются от норм
  (ГСМ, оклады, вагоны 62 тн, резка, пресс, распределяемые баз); нормы —
  в справочнике `cost_norms`, общие + переопределения по базам.
- **Аукционная лестница**: P&L на каждом шаге торгов, предельный шаг при
  рентабельности ≥ порога.
- **График вывоза** (`/bp/N/schedule`): остатки → отгрузка → реализация
  с потерями (по умолчанию 3%) по базам и месяцам; попадает в xlsx.
- **Сценарии цен**: консервативный/базовый/оптимистичный (±Δ руб/тн).

## Сопоставление номенклатуры с 1С

Позиции продавца (Лукойл и др.) автоматически сопоставляются с номенклатурой
1С (28 тыс. позиций, лист «Номенклатура» выгрузки): точное совпадение
нормализованных имён → нечёткий подбор. Подтверждённые мастером пары
сохраняются в `nomen_match_history` и предлагаются в следующих БП с пометкой
«предложено на основе ИИ». Финальная корректировка — вручную через
автокомплит (блок «3а» карточки). Номенклатура 1С и GUID попадают в лист
«Данные» БП и в таблицу «Выручка» — отчёт встаёт в 1С по своим позициям.
Логика подбора: `app/matcher.py`.

## Граф маршрута

Вкладка «Маршрут сделки»: узлы (продавец, базы, цех, производство,
ответхранение, покупатель — продавец/покупатель из контрагентов 1С, базы из
складов 1С с дивизионами), пути с транспортом и тоннажом, процессы на узлах
со сменой номенклатуры (виды работ из 1С: перемотка, разборка ПЭД и т.д.).
Узлы перетаскиваются, позиции сохраняются. План по транспорту и переработке
в выгрузке формируется из графа.

**Стрелки связаны со строками затрат** (`bp_costs.edge_id`): к каждому пути
привязываются конкретные статьи (существующие или новые — из формы в таблице
«Пути»), сумма затрат и руб/тн показываются на стрелке графа; толщина
стрелки — по тоннажу. Затраты стрелки распределяются на позиции всех баз,
чьи потоки проходят через неё (обход графа назад: стрелка из узла
консолидации несёт затраты и для позиций баз, из которых в узел ведут пути).

**Граф строится из данных БП** (кнопка «Построить граф из данных БП»):
базы и объёмы — из позиций лота, транспорт — из вида отгрузки позиций,
статьи затрат с базой автоматически привязываются к стрелкам (сопоставление
имён по значимым словам с ранжированием: точное > вложенное > пересечение).
Топология у каждого БП своя. Консолидация и перегрузы добавляются операцией
«вставить узел в путь»: стрелка A→B разрезается на A→M и M→B, затраты
остаются на первом плече (отмеченные галочками переезжают на второе), потоки
в существующую стрелку M→B сливаются с суммированием тоннажа.

**Проверка графа по данным БП** (блок на странице маршрута): у каждой базы
позиций есть узел; выход каждого узла = свой объём + транзит; покупатель
получает весь тоннаж лота; статьи с базой привязаны к стрелкам; стрелки без
затрат подсвечиваются. Граф — модель сделки, расхождения видны сразу.
