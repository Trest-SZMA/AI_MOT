2. Единицы измерения → тонны (§7)

  • Тоннаж считается построчно: единица берётся из справочника номенклатуры по ГУИДу строки (иначе по имени), спорные коды перечислены явно в UNIT_BY_CODE. Единица не берётся из файла остатков — эталон сверки не должен влиять на измеряемое (12.08.2026).
  • т = 1; кг = 0,001; г = 1e-6. Базовая «м / пог.м», «единица для отчётов = т» и коэффициент → метры делятся на коэффициент (НКТ 73 — 106…108,7 м/т, НКТ 60 — 141…147, НКТ 89 — 76…80).
  • Штуки, комплекты, пары, литры, м³, км, уп, рулоны в тонны не превращаются — во всём сервисе (контрольный пример 7). Единственное исключение — вкладка «Остатки», см. §9.
  • Единица — самостоятельный разрез отчёта (тонны · штуки · метры · литры · …). Суммы разных разрезов не складываются. Номенклатура с коэффициентом видна в двух разрезах сразу (32 м и 0,218 т).
  • Выявленные ошибки справочника 1С (16.09.2026, на расчёт пока не влияют): «Труба НКТ 102*6,5 б/у (м)» и «Труба НКТ 114 мм б/у (м)» — 1 м = 1 т; «Электродвигатель» и «Трансформатор ТМ-6,3 б/у (шт)» — 1 шт = 1 т; «Блок погружной б/у» — базовая «т» при штучном учёте (принудительно «шт»).

3. Серия, бизнес-план, проект

  • Бизнес-план — это ПРОЕКТ (ПроектГуид справочника серий), а не номер договора: «… V» и «… VS» — варианты одной серии (довозы и пересорт). Ведущий номер серии ключом быть не может — он склеивал 18 проектов «1291032 … СП N».
  • Головная серия — без «V»/«VS». Сравнение с планом Excel («Закупка по БП») идёт только по ней: «что написано в Excel, то должно пройти по головной серии».
  • Номер БП берётся из «Проверки БП» Битрикса, а если там проекта нет — из имени серии: ведущая группа из 2–4 цифр («545 (21/136…)»), при «344/345» — тот номер, у которого есть версия расчёта (14.09.2026).
  • Каскад восстановления серии для строки без серии 1С, сверху вниз, первое сработавшее побеждает; результат помечен бейджем происхождения:
    1. ручная привязка overrides.json — ручная;
    2. серия записана в самой строке 1С — 1С (высший приоритет);
    3. склад закреплён за единственной серией — склад;
    4. смешанный лот: точное количество → аллокация по ёмкости → деление — док / доля;
    5. перемещение: приходная сторона берёт серию расходной того же документа и той же партии — док;
    6. карта «партия + код» по всей выгрузке — док;
    7. наследование при переработке — переработка (четыре ограничения: локальность по складу, доминирование ≥ 50 % от ВСЕГО сырья, присутствие серии на складе; документ опознаётся по регистратору);
    8. единственная серия, приходившая на склад под этим кодом — вероятно;
    9. договор и номер БП из имени договорной площадки — площадка;
    10. ВВОД ОСТАТКОВ / ИЗЛИШКИ — ввод; иначе — БЕЗ СЕРИИ (нет).
    При агрегации побеждает худший бейдж позиции.
  • Серия-донор (14.09.2026, БП 773/690): на ключе «склад + код» серия с отрицательным остатком закрывается серией, которая на этот склад приехала перемещением и имеет плюс; переписываются расходные строки минусовой серии, самые поздние первыми, не больше, чем донор привёз и чем у него осталось; порог 0,5 т; внутри одного проекта (серия и её V/VS) не применяется. Бейдж донор.
  • Псевдо-серии. «площадка:<договор>» — металл договорных площадок без серии 1С; «БЕЗ СЕРИИ» — всё, что восстановить нельзя (в 1С это «Объём №1», подтверждено 12.08.2026). В «Закупке по БП» площадки, серии без номера БП и БЕЗ СЕРИИ вынесены в «старые БП» и в общий счётчик не входят (14.09.2026).
  • Лоты. Ключ лота = тип документа + номер (+ дата для переработки): один номер бывает у разных документов. Пустая партия лотом не считается. Перемещение лот не тратит.
  • Смешанные лоты (приход нескольких серий): 1) точное количество; 2) аллокация по неизрасходованной ёмкости, строки по дате; 3) только если не влезает — деление с бейджем доля и записью в «Проблемы». Компоненты меньше 1 % и всё сверх четырёх сворачиваются в доминирующую серию.

5. Остаток

  • ОСТАТОК = приход − расход по всем потокам на ключе «серия · вариант серии · склад · номенклатура»; колонка складывается снизу вверх на всех уровнях дерева. Внутренние потоки входят обеими сторонами.
  • С 14.09.2026 остаток считается КАК В 1С — везде (Ганта, деревья, сводные, «Остатки», Excel): односторонние переработки входят в остаток (тонны, ставшие штуками, из тоннажного остатка уходят; лом от разборки — приходит). Прежнее правило 11.08.2026 (БП 1586: односторонние — диагностика) отменено. Проверено: складской и проектный остаток по компании равны, сверка с регистром остатков 1С по 15 861 ключу «склад × код» — Δ 0,97 т.
  • Формула в приходе: купили (нетто возврата) + приехало + из производства + из сортировки + излишки + ввод остатков + пересортица + вернул клиент + корректировки + приход без пары; в расходе: уехало + в производство + в сортировку + продали + недостачи + на затраты + внутренний оборот + расход без пары. Приход через разборку в остатке считается один раз.
  • Отрицательный остаток — расход в регистре больше прихода (ранний приход до начала выгрузки, серия сменилась в пути, ошибка серии в 1С); подсвечен красным, не «исправляется».
  • Обратный ход (автопроверка): остаток на дату = факт снимка 1С + расход после − приход после; сверяется только пересечение складов со снимком.

7. Продажи, выручка, маржа

  • Продажа — строка расхода с регистратором «Реализация товаров и услуг» (внешний покупатель). Позиция = документ × номенклатура × серия; тоннаж и количество как в документе.
  • Факт выручки (14.09.2026) — регистр 1С «Выручка и себестоимость продаж», без НДС. Ключ связки — номер документа реализации + имя номенклатуры; рубли раздаются по сериям пропорционально нашему количеству в тех же строках. Себестоимость продаж — из того же регистра. Маржа = выручка − себестоимость. В «Закупке по БП» — только по головной серии.
  • Регистр охватывает три наши организации; документы других организаций (МО-/АР-/ИВ-) в выручку пока не разделяются (решение 14.09.2026: «пока не разделяй»).
  • Оплаты за лом привязаны к БП по ГУИДу проекта из заявки на расходование; дата — «ДатаПлатежа», иначе из имени регистратора. Привязка по договору не делается.

8. Закупка по БП (план из Excel против факта 1С)

  • Строка — бизнес-план, внутри наша НМК × склады оприходования; только головная серия. Куплено — «купили» из движений, продано — по тем же позициям, факт выручки — из регистра.
  • Версия расчёта: отмеченная экономистом верной на «Версиях БП»; если отметки нет — последний лист файла за версию (14.09.2026), отдельно по трекам «лук» и «дсп». Отклонённая версия из расчётов исключена. Позиции версии — с листа расчёта, при #REF! — с листа «перечень».
  • Сопоставление плановых позиций с нашей НМК — по смыслу, а не по тексту: вид (лом / труба / штанга / полуштанга / кабель / цветмет), марка лома, размеры (для трубы — дюймы переводятся в мм: 2,375″→60, 2,875″→73, 3,5″→89, 4,5″→114, 1¼″/1½″/1,9″→48; 14.09.2026), сечение кабеля; марка и размер — вето; при равных кандидатах предпочитаются купленные позиции, затем сходство имён, затем самое короткое имя (только при уверенном совпадении). Что не разнеслось — считается под таблицей: «марка в плане не указана» (лом без марки при нескольких марках в факте долями не раскладывается) и «не сошлось с нашей НМК».
  • План по складам: место хранения из Excel сопоставляется с нашим складом по городу / площадке (словарь сокращений), показано рядом с фактом склада.
  • Доля лота и юрлицо (реестр сделок Битрикса, 14.09.2026): колонки «план × доля» — наш факт сравнивается с планом, умноженным на нашу долю; доля со знаком «?» помечена как сомнительная; без записи о сделке колонок «план × доля» нет.
  • Старые БП (площадки, серии без номера БП, БЕЗ СЕРИИ) — отдельный переключатель, в общий счётчик не входят (14.09.2026).
  • Сумм закупки в рублях в выгрузке 1С нет (только количества) — колонка ждёт отдельного поля от 1С.

9. Вкладка «Остатки» (сверка с 1С)

  • Те же строки движений и те же правила, что в дереве, в разрезе отчёта 1С: корень справочника подразделений → регион / база → подразделение (как в колонке регистра) → группа аналитического учёта («Номенклатурная группа грузов» справочника) → номенклатура → (бизнес-план, если выбрана вся компания). Регионы старых складов из папок сведены к именам справочника («Юг» = «Южный регион», «Пермь» = «Пермский край»).
  • Вариант ограничивает только склады (заготовка / все); столбцы — все потоки, какие есть в выборке; ОСТАТОК — первой числовой колонкой; итог по бизнес-плану сверяется с остатком его строки на Ганте (карточка «на Ганте», допуск 0,005 т).
  • Исключение из §7 — только здесь (16.09.2026): штучная номенклатура, у которой в справочнике 1С «единица для отчётов = т» и коэффициент ≠ 1 (штанги 58,8 шт/т, трансформаторы 100 кВА 3,33 шт/т, крышки люков 5,88 шт/т, колёсные пары 0,834 шт/т, автосцепки, поглощающие аппараты), переводится в тонны по коэффициенту — как в отчёте 1С «в тоннах». Такие строки помечены «шт→т», их вклад показан отдельной карточкой и в сверку с Гантой не входит. Заглушки «1 шт = 1 т» не берутся. На остальных вкладках эти тонны не считаются.
  • Плашка вверху — дата выгрузки регистра из 1С (см. §1).

10. Сверки, автопроверки, контрольные примеры

  • Инварианты (расхождение = ошибка расчёта): сумма позиций = прямой пересчёт по сырым строкам; недоезд по компании ≈ 0; в производство = из производства по каждому БП (с учётом односторонних).
  • Вопросы к данным 1С (помечаются «!», расчёт не меняют): продано > поступило по серии; уехало ≠ приехало по серии (серия сменилась в пути); оплаты без БП; планы Битрикса без привязки; позиции с бейджами «нет» / «вероятно» — на валидацию.
  • Остаток по движениям vs факт 1С — по пересечению складов со снимком остатков; обратный ход по ключам «склад × код».
  • Контрольные примеры §12 (tools/control_check.py, 10 штук — конкретные документы, лоты и БП с ожидаемыми цифрами: РУМЛ-001175, РУ00-009885, РУМЛ-000146, БП 1578, БП 164, РУМЛ-003097, БП 1586 и др.). Сборка публикуется, только если пройдено не меньше, чем в прошлой.
  • Тождество таблицы «Закупки / продажи»: поступило − выбыло − потери переработки − недоезд − остаток = невязка (должна быть 0).

11. Чего в коде нет намеренно

  • Нет FIFO при подборе лота — у строки продажи есть своя партия.
  • Нет пропорционального деления по умолчанию — только точное количество и ёмкость; деление — крайний случай с пометкой.
  • Нет привязки по договору — под одним договором десятки проектов.
  • Нет пересчёта штук в тонны (кроме вкладки «Остатки», §9).
  • Нет выдуманного дивизиона, подразделения или срока: если из данных не следует — честный прочерк («—», «без плана», «регион не указан»).
  • Нет раскладки плана «металлолом без марки» долями по маркам факта.
