# МетОптТорг — сервис оценки КП и выходов металлов

Серверный веб-сервис: загрузка перечней НВО МТР от продавцов → сопоставление со
справочником 1С → два сценария оценки (база / БП) → предельная цена выкупа →
экспорт в Excel. Полная спецификация: `../ПРОМПТ_МетОптТорг_v2.md`.

## Запуск (разработка)

```bash
cd metopttorg
python3 -m venv .venv
.venv/bin/pip install fastapi uvicorn sqlalchemy openpyxl pdfplumber pytest python-multipart
.venv/bin/python scripts/load_all.py           # загрузка dev-базы из data/samples
.venv/bin/python -m uvicorn app.api.main:app --port 8017
# UI: http://localhost:8017
```

Выгрузки 1С (цены, разборка, логистика, сделки по контрагентам):

```bash
.venv/bin/python scripts/load_1c.py          # все выгрузки из data/1c
.venv/bin/python scripts/load_1c.py deals    # только сделки по контрагентам
```

Прод: PostgreSQL через `DATABASE_URL=postgresql://...` (по умолчанию SQLite в data/).

## Структура

- `app/normalize.py` — нормализация имён, семейства, типоразмеры, марки лома
- `app/db/models.py` — схема БД (items, item_aliases, component_yields,
  cable_brands, expert_yields, expert_metal_profiles, kp_*, scrap_prices…)
- `app/importers/`
  - `nomenclature.py` — справочник 1С: отбор торговых, дедуп (guid → aliases)
  - `cable_files.py` — кабельные справочники (Оценка_металла, ННОС, ПНОС,
    Таблица по маркам, ВНПЗ) со сверкой контрольных итогов
  - `metal_yields.py` — «Выходы металлов» (3 формата), детект xlsx-«скана»,
    профили семейств
  - `kp.py` — импорт КП (Excel/CSV/PDF), автодетект заголовков, агрегация
    лотов, каскад сопоставления
- `app/calc/`
  - `cable.py` — парсер маркировки кабеля, медь 8,9 / алюминий 2,7 кг/км/мм²
  - `engine.py` — сценарный расчёт и формула выкупа
  - `deals.py` — история сделок по контрагентам из «Движение ТМЦ»: кто, что,
    когда, почём и через какого менеджера. Источник вкладки «Клиенты»
- `app/calc/`
  - `price_ladder.py` — каскад цены реализации: своя продажа → карточка-двойник
    → тот же габарит ряда → регрессия по модельному ряду → закупка × наценка →
    медиана семейства → внешние источники. Каждая ступень возвращает основание
- `app/leads/` — подбор покупателей
  - `internal.py` — лиды из своей истории с уровнями родства позиции
  - `pricing.py` — ценовой коридор: пол по металлу / ориентир / потолок рынка
  - `web.py` — внешние источники (профиль товара, закупки ЕИС, отраслевой поиск)
  - `service.py` — кампания подбора, фоновая, с прогрессом по стадиям
- `app/ai_client.py` — общий клиент ИИ-провайдера с подсказками торговых площадок
- `app/api/main.py` — FastAPI + экспорт Excel; `web/index.html` — UI без CDN
- `tests/` — 98 тестов, в т.ч. на реальных файлах со сверкой итогов

## Вкладка «Клиенты» — кому продать и по какой цене

Отвечает на вопрос по залежавшейся позиции: кто это купит и за сколько.
Порядок стадий подобран так, чтобы результат был полезен без интернета.

1. **Ценовой коридор** — пол по металлу, ориентир (каскад `price_ladder`),
   потолок (90-й процентиль наших продаж по типоразмеру/ряду/семейству).
2. **Покупатели из истории сделок** — 1С помнит их лучше, чем отдел продаж.
   Лид ранжируется по родству позиции (ровно эта → типоразмер → модельный ряд →
   семейство), свежести и объёму. Ломовые покупатели идут отдельным каналом:
   они дают пол цены, а не цену изделия.
3. **Объявления «куплю»** из отслеживаемых каналов (вкладка «Мониторинг») —
   это новые покупатели с контактом, а не наши старые клиенты.
4. **Внешние источники** (нужен ключ провайдера): профиль товара, закупки в ЕИС,
   отраслевые покупатели. Компания, которая уже есть среди наших контрагентов,
   не дублируется — внешняя находка усиливает существующего лида; наименования
   сводятся ключом `company_key` («ООО «Союз-Техно»» = «СОЮЗ-ТЕХНО ООО»).

Под каждым лидом лежит доказательство: строка сделки из 1С или ссылка.
Статусы лида (новый / в работе / отказ / сделка) ведёт менеджер. Кнопка
«Письмо» даёт черновик — **сервис ничего не отправляет сам**.

Главный список — **новые** покупатели. Наши действующие клиенты вынесены в
отдельный свёрнутый блок «Уже покупали у нас»: искать их не надо, их ведёт
отдел продаж, но цена, которую они платили, — самое достоверное основание для
нашей цены, поэтому из расчёта коридора они не исключены.

Важное ограничение: цена контрагента переносится на нашу позицию только при
близком родстве. «КАМЭЛЕКТРОПРИВОД платил 400 000 ₽/шт» — правда, но за
СТДМ-1250, а не за ВДМ 60, и как ожидаемая цена такая цифра не показывается.

## Вкладка «Мониторинг» — торговые каналы

Три вида источников:

* **Telegram-канал** — читается веб-просмотр (`t.me/s/<канал>`): ключи и вход в
  аккаунт не нужны, это та же страница, что видит любой человек по ссылке.
  Закрытые каналы, группы и чаты так не читаются — для них понадобился бы
  отдельный Telegram-аккаунт компании (MTProto), это отдельное решение.
  Ссылка-приглашение в папку (`t.me/addlist/…`) списка каналов не раскрывает:
  Telegram отдаёт только имя папки и число чатов, юзернеймы разворачивает
  приложение — их придётся выписать руками.
* **Поисковый запрос** — уходит в ScrapeGraphAI (`/api/search`), тот ищет по
  сети и отдаёт найденные страницы, а разбирает их наш собственный
  `app/monitor/parse.py`. ИИ-извлечение на стороне сервиса сознательно не
  включено: замер показал минуты против пяти секунд у обычного поиска, а
  заголовок объявления и так несёт главное — «Куплю ПЭД (погружной
  электродвигатель) б/у». Со страницы берутся не первые полторы тысячи знаков
  (это меню и баннеры), а строки с ценой, телефоном или намерением.
  Формулировка запроса решает: «куплю <позиция> б/у» находит покупателей,
  «<позиция> купить» — каталоги продавцов.
* **Страница сайта** — разбирается через ScrapeGraphAI (`/api/extract`) по
  текстовому описанию, без ручных правил под каждую вёрстку.

Последние два требуют `SGAI_API_KEY` в `/etc/metoptorg-kp.env`; без него они
недоступны, а Telegram работает как работал.

**Сеть.** С сервера 192.168.6.157 домен `v2-api.scrapegraphai.com` (адреса
Render 216.24.57.x) недоступен: до одного адреса не открывается TCP, до второго
открывается, но не завершается TLS. При этом `cloudflare.com` и
`api.perplexity.ai` с того же сервера работают, а с рабочей станции сервис
отвечает за полсекунды — то есть закрыт именно этот домен, как раньше
OpenRouter. Клиент перебирает все адреса домена (сохраняя проверку сертификата)
и умеет ходить через прокси: `HTTPS_PROXY` или `SGAI_PROXY` в
`/etc/metoptorg-kp.env`. Пока сеть не открыта, источники «поиск» и «страница»
на сервере честно сообщают об этом в колонке «Состояние».

Список каналов из папки Telegram добавляется пачкой — кнопка «Список пачкой»
принимает столбец имён и по каждому отвечает отдельно: добавлен или почему нет.

**Про Avito.** Открытого API для чужих объявлений у него нет, прямое чтение
отдаёт 429 и запрещено robots.txt. ScrapeGraphAI умеет обходить защиту от
роботов, но само по себе это не делает чтение чужого сайта разрешённым: правила
площадки остаются в силе, и решение, какие адреса заводить источниками, —
хозяйское. Сервис ни одного адреса Avito сам не добавляет.

## Ключевые слова

Классификатор семейств выучен на справочнике 1С — он узнаёт только то, что уже
проходило через компанию. Ключевые слова закрывают остальное: новую марку,
редкую позицию, чужую формулировку. Два режима:

* **целым словом** — для аббревиатур: «ПЭД» не сработает внутри «ПЭДАЛЬ»;
* **с окончаниями** — поиск по основе, ловит падежи: «гидрозащита» находится
  во фразе «куплю гидрозащиту».

Объявление считается интересным, если распозналась позиция **или** сработало
слово. Кнопка «Пересканировать ленту» применяет список к уже собранным
объявлениям — иначе новое слово работало бы только на будущих.

Из ленты извлекаются ровно две вещи:

* «куплю» → **новый покупатель** с контактом; такие объявления попадают в
  подбор клиентов отдельным каналом и стоят там выше отраслевого поиска:
  это не догадка о профиле, а человек, который ищет позицию прямо сейчас;
* «продам» с ценой и распознанной позицией → рыночный ориентир
  (`price_quotes.used_market_offer`), то есть низ каскада цены.

Внешняя цена пускается в каскад с оглядкой: только когда объявление село на
конкретную карточку, единица совпала и цена не расходится с нашей оценкой
более чем впятеро. Ошибка разбора чужого текста не должна двигать наши КП.

Периодичность фонового опроса — `MONITOR_INTERVAL_MIN` (по умолчанию 30 минут,
`0` выключает).

## Эксплуатация на сервере

```bash
./scripts/deploy.sh            # тесты → код → перезапуск → проверка чтения И записи
./scripts/deploy.sh --with-db  # то же, но с заливкой базы (правит владельца файла)
```

- Вход: **сейчас выключен** (`METOPTTORG_AUTH=off` в `/etc/metoptorg-kp.env`) —
  сервис доступен всем в сети, все действия под ролью директора.
  Чтобы вернуть вход: убрать эту строку и `systemctl restart metoptorg-kp` —
  учётные записи сохранены. Роли: `директор` (нормативы, цены лома, выхода,
  импорт справочника) и `оценщик` (КП, корректировки, экспорт).
- Пользователи: `scripts/user_admin.py list|add|passwd|disable` на сервере,
  с `METOPTTORG_DATA_DIR=/var/lib/private/metoptorg-kp`.
- Бэкапы: таймер `metoptorg-kp-backup.timer`, ежедневно 03:30, 14 копий в
  `/var/backups/metoptorg-kp`. Восстановление:
  `gunzip -c metopttorg_ДАТА.db.gz > /var/lib/private/metoptorg-kp/metopttorg.db`
  и `chown` под UID службы.
- ИИ-поиск цен: ключ провайдера в `/etc/metoptorg-kp.env` (root, 600).
  С этого сервера работает Perplexity; OpenRouter отдаёт 403 (его защита).
  Поиск идёт лестницей запросов (полное имя → марка с габаритом → марка) и
  просит СПИСОК предложений с состоянием, а не одно число; агрегация и отбор
  выбросов — в питоне. Находка, расходящаяся с оценкой по нашим фактам более
  чем впятеро, отклоняется: завышенная внешняя цена опаснее её отсутствия.
- После выкатки на сервере нужны сделки по контрагентам, иначе вкладка
  «Клиенты» пуста: либо `scripts/load_1c.py deals` на сервере (нужны выгрузки
  в `data/1c`), либо `./scripts/deploy.sh --with-db` — он зальёт локальную базу
  вместе с загруженной историей (учётки скрипт сохраняет и возвращает).
