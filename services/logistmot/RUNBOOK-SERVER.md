# ЛогистМОТ — развёртывание на сервере (Linux)

Для Ubuntu/Debian с systemd. Нужен доступ root (sudo).

## Зачем сервер

Бот и панель работают круглосуточно, не зависят от офисного компьютера,
перезапускаются сами (после падения и после перезагрузки сервера).

## Порядок переезда (важна последовательность!)

**Бот должен работать только в одном месте.** Поэтому:

1. **Остановите бота на Windows** (закройте окна BOT и PANEL, уберите ярлыки
   из автозагрузки `shell:startup`). С этого момента события копятся на
   сервере MAX и будут дособраны после запуска на сервере.

2. **Заберите с Windows свежие файлы**: `bot.db` (вся база!) и `.env`
   из папки бота.

3. **На сервере** распакуйте архив `logistmot_server.tar.gz`:
   ```bash
   sudo mkdir -p /opt/logistmot
   sudo tar xzf logistmot_server.tar.gz -C /opt/logistmot
   ```

4. **Положите свежие `bot.db` и `.env`** (из шага 2) в `/opt/logistmot/`,
   заменив имеющиеся.

5. **Настройте `.env` для сервера** — добавьте/проверьте строки:
   ```
   PANEL_HOST=0.0.0.0
   PANEL_PORT=8080
   PANEL_USER=logist
   PANEL_PASSWORD=<придумайте-надёжный-пароль>
   ```

6. **Установите**:
   ```bash
   sudo bash /opt/logistmot/deploy/install_server.sh
   ```
   Скрипт ставит окружение, создаёт службы systemd `logistmot-bot` и
   `logistmot-panel`, включает автозапуск и сразу стартует. Установщик
   откажется запускать панель в сеть без пароля.

7. **Проверка**: напишите боту в личку «проверка сервера» — строка должна
   появиться в журнале:
   ```bash
   journalctl -u logistmot-bot -f
   ```

## Доступ к дашборду

Панель слушает порт 8080 на всех интерфейсах, вход — по логину/паролю из `.env`
(браузер сам покажет окно входа).

**Вариант А — офисная сеть / VPN (рекомендуемый старт).**
Логисты открывают `http://<ip-сервера>:8080`. Ограничьте порт файрволом
только доверенными адресами:
```bash
sudo ufw allow from <подсеть-офиса>/24 to any port 8080
sudo ufw deny 8080
```

**Вариант Б — доступ из интернета по-взрослому (когда понадобится).**
Домен + nginx с HTTPS-сертификатом (Let's Encrypt) как обратный прокси к
127.0.0.1:8080; тогда в `.env` вернуть `PANEL_HOST=127.0.0.1`. Логисты открывают
`https://panel.вашдомен.ru` с тем же паролем. Скажите разработчику домен —
конфиг подготовим.

**Вариант В — точечный доступ одному человеку без открытия портов:**
SSH-туннель `ssh -L 8080:localhost:8080 user@сервер` и открыть
`http://localhost:8080` у себя.

## Эксплуатация

```bash
systemctl status logistmot-bot logistmot-panel   # статус
journalctl -u logistmot-bot -n 100               # последние события бота
sudo systemctl restart logistmot-bot             # перезапуск (после правки .env)
```

Обновление кода: заменить нужные .py файлы в /opt/logistmot и
`sudo systemctl restart logistmot-bot logistmot-panel`.

Резервная копия — один файл: `/opt/logistmot/bot.db`
(например, в cron: `cp /opt/logistmot/bot.db /backup/bot-$(date +%F).db`).

## Безопасность

- `.env` содержит токен бота — права 600, никому не пересылать.
- Панель без пароля наружу не открывать (установщик это контролирует).
- Порт 8080 — только для доверенных сетей (ufw, см. выше).
